# Развёртывание на сервере

Сервер: Linux с Docker Engine и Docker Compose v2.24+, 2 ГБ памяти и больше, открытые порты
80 и 443 (для встроенного HTTPS) и DNS-запись `A` домена на адрес сервера.
Python, Node.js и PostgreSQL на сервере не нужны: всё собирается в контейнерах.

## Состав

| Сервис | Назначение | Снаружи |
|---|---|---|
| `db` | PostgreSQL 17, данные в томе `pgdata` | нет |
| `migrate` | применяет проверенные миграции и завершается | нет |
| `app` | API и WebSocket досок, один процесс (доски живут в памяти процесса) | нет |
| `web` | nginx: сайт и прокси `/api` с апгрейдом WebSocket | `127.0.0.1:8080`, если нет Caddy |
| `caddy` (профиль `https`) | HTTPS с автоматическим сертификатом для `SHAD_DOMAIN` | 80, 443 |

Серверная надстройка — `docker-compose.prod.yml`: закрывает внешние порты API и БД, ограничивает
размер логов, передаёт API реальный адрес посетителя (лимиты входа на доски), добавляет Caddy.

## Первый запуск

```sh
git clone https://github.com/senia-glitch/ProjectSHAD_Diplom_work.git shad
cd shad
sh deploy/deploy.sh init        # .env.production с новыми паролем БД и JWT-секретом (права 600)
nano .env.production            # SHAD_DOMAIN=example.ru, SHAD_TIMEZONE=Europe/Moscow
sh deploy/deploy.sh up          # сборка, миграции, запуск; ждёт готовности всех сервисов
sh deploy/deploy.sh admin admin admin@example.ru   # первый администратор, пароль вводится скрытно
```

Если на сервере уже есть свой обратный прокси (nginx, Traefik), оставьте `SHAD_DOMAIN` пустым:
сайт будет слушать `SHAD_BIND:SHAD_HTTP_PORT` (по умолчанию `127.0.0.1:8080`). Прокси должен
передавать заголовки `Upgrade`/`Connection` для `/api/v1/boards/*/ws` и `Host` без изменений.

Демо-данные (`scripts.seed_demo`) на сервере не запускаются. Ученики и репетиторы регистрируются
сами; администратора создаёт только `deploy.sh admin` (открытая регистрация администраторов не создаёт).

## Обновление

```sh
sh deploy/deploy.sh backup      # копия БД перед обновлением
sh deploy/deploy.sh update      # git pull --ff-only, пересборка, миграции, перезапуск
```

Сервис `migrate` применяет только закоммиченные ревизии Alembic; приложение при старте проверяет,
что схема совпадает с моделями, и не меняет БД само. При остановке `app` сохраняет открытые доски
(даётся 30 секунд).

## Резервные копии

```sh
sh deploy/deploy.sh backup                      # backups/shad-ГГГГММДД-ЧЧММСС.sql.gz
sh deploy/deploy.sh restore backups/shad-....sql.gz   # спросит подтверждение, заменит данные
```

Папка `backups/` в git не попадает. Для регулярных копий добавьте в cron, например:
`0 3 * * * cd /opt/shad && sh deploy/deploy.sh backup`, и переносите копии за пределы сервера.

## Секреты и настройки

- `.env.production` хранит пароль БД и `CORE_JWT_SECRET`; в git и в образы не попадает.
  Смена `CORE_JWT_SECRET` завершает все сессии и делает недействительными коды досок
  (код хранится как HMAC с этим секретом).
- `BOARD_ALLOWED_ORIGINS` — только если сайт открыт с нескольких доменов; по умолчанию WebSocket
  принимается лишь с того же адреса, что и сайт.
- `BOARD_RETENTION_DAYS` — через сколько дней без входов доска удаляется (по умолчанию 365).

## Проверка после запуска

```sh
sh deploy/deploy.sh ps                          # все сервисы healthy
curl -fsS https://example.ru/api/v1/ready       # {"status":"ready"}
```

В браузере: вход администратором, регистрация тестового репетитора, создание доски и вход на неё
со второго устройства по коду.

## Что проверено перед релизом

Конфигурация `docker-compose.yml` + `docker-compose.prod.yml` поднята в отдельном проекте на
Docker Desktop: все сервисы healthy, наружу опубликован только сайт, процесс API работает не от root
и без pytest в образе, `create_admin` создаёт администратора и отказывает при повторе, вход
администратора и его страницы работают, WebSocket доски проходит через nginx, чужой Origin
отклоняется, `pg_dump` формирует копию, заголовки безопасности nginx на месте.
Профиль `https` (Caddy и выпуск сертификата) проверен только на уровне конфигурации:
для выпуска сертификата нужен настоящий домен.
