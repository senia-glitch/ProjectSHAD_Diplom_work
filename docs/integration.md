# Объединение проектов

Основа — SHAD Tutoring (этот репозиторий). В него встроены три проекта; их исходные
репозитории не изменялись.

| Источник | Что перенесено | Где теперь |
|---|---|---|
| [ProjectSHAD_Diplom_testirovanie](https://github.com/senia-glitch/ProjectSHAD_Diplom_testirovanie) | тесты из 9 типов заданий (45 вариантов), выдача доступа, попытки, автопроверка, оценка репетитора | `app/scenarios/testing/`, `app/api/v1/routes/testing.py`, `frontend/src/ui/legacy/testing/kit.js`, страница `/testing` |
| [ProjectSHAD_Diplom_work_doska](https://github.com/senia-glitch/ProjectSHAD_Diplom_work_doska) | совместная доска: WebSocket, вход по коду, чат, автосохранение, файл `.doska.json`, права создателя | `app/realtime/`, `app/scenarios/boards/`, `app/api/v1/routes/boards.py`, `frontend/src/ui/legacy/board/`, страницы `/boards`, `/boards/:id` |
| [My_Blog](https://github.com/senia-glitch/My_Blog) | визуальный язык ProjectProgon (токены, шапка, лента, карточки, формы); идея личного блога | `frontend/src/ui/styles/pp.css`, `MainLayout.vue`; блог репетитора `app/scenarios/blog/`, страницы `/blog*` |

## Единые правила

- **Один стек и одна БД:** event-infra + core-package + fastbase + PostgreSQL, один процесс.
  Новые таблицы добавлены ревизией `alembic/versions/20261124_modules_integration_modules.py`
  (только создание таблиц; старые данные не затрагиваются).
- **Одни пользователи и роли:** преподаватель из системы тестирования — это репетитор (`tutor`),
  ученик — `student`. Регистрация и вход — прежние, отдельных учётных записей у модулей нет.
- **Одна политика доступа** — `config/access.toml`. Неописанное действие запрещено.
  WebSocket доски объявлен действием `boards.live` и проверяет токен в первом сообщении.
- **Связь репетитор — ученик** (`configurations`) определяет, кому репетитор может открыть тест:
  в списке доступа — только свои ученики. Снятый доступ закрывает тест сразу.

## Тестирование

Права и поведение сохранены: тест создаёт репетитор, изменение теста создаёт новую версию,
ученик видит только результаты текущей версии, репетитор видит и прежние с пометкой.
Таблицы: `quizzes`, `quiz_access`, `quiz_attempts`. API: `/api/v1/testing/tutor/*` и
`/api/v1/testing/student/*`. Интерфейс модуля перенесён как один ES-модуль: страницы строят DOM,
Vue-страница `ui/pages/testing` монтирует их и передаёт транспорт приложения (токен и обновление
сессии) и навигацию vue-router.

## Доски

- Создаёт доску **репетитор**; входят вошедшие пользователи по коду (ученики и репетиторы).
- Ключ участника выдаёт сервер: HMAC от `users.id`. Поэтому владелец входит на свою доску
  без кода с любого устройства, а участник, однажды вошедший по коду, — повторно без кода.
- Имя на доске берётся из профиля, переименование на доске отключено.
- Хранение кода, исключение участников, лимиты, автосохранение — как в исходном проекте.
  Настройки — переменные `BOARD_*` (см. `app/core/board_settings.py`); срок хранения досок без
  входов по умолчанию 365 дней. `BOARD_ALLOWED_ORIGINS` нужен, только если frontend открыт с
  другого адреса, чем API (например, Vite-сервер разработки).
- Таблицы: `boards` (+ `owner_id`), `board_strokes`, `board_chat_messages`, `board_members`.

## Блог репетитора

- Каждый репетитор ведёт свой блог: записи в Markdown, черновики, теги, закрепление.
- Опубликованные записи читают все, включая гостей: лента `/blog`, блог автора
  `/blog/authors/:id`, запись `/blog/posts/:id`. Черновик видит только автор.
- Комментарии пишут вошедшие пользователи; удалить может автор комментария, автор записи
  или администратор. Управление записями — `/blog/manage` (раздел «Блог» в меню репетитора).
- Таблицы: `blog_posts`, `blog_comments`. Markdown безопасный (тот же рендерер, что у тестов):
  текст экранируется, медиа — только по внешним ссылкам.

## Дизайн

Эталон — My_Blog (ProjectProgon). Токены приложения приведены к его палитре
(`ui/styles/tokens.css`), шапка и подвал построены на его классах: на компьютере разделы —
значки 48 px с подсказками и акцентной линией активного раздела, на телефоне — прокручиваемая
текстовая строка. Стили ProjectProgon собраны в `ui/styles/pp.css` и действуют только внутри
контейнера `.pp`, поэтому существующие страницы расписания и статистики не ломаются.
Совмещение с базовыми стилями — `ui/styles/pp-fixes.css`.
