# Правила архитектуры фронтенда

Стек: Vue 3, Vite, Pinia, Vue Router.
Правила описывают архитектуру любого проекта на этом стеке.
Применимы независимо от предметной области.

---

## 1. Термины
|---------------------------|-----------------------------------------------------------------------------------------------------------|
| Термин                    | Определение                                                                                               |
|---------------------------|-----------------------------------------------------------------------------------------------------------|
| Слой                      | Уровень ответственности. Верхний уровень — `logic/` и `ui/`.                                              |
| Модуль                    | Файл, предоставляющий контракт, или папка с `index.js`.                                                   |
| Домен                     | Предметная область. Имя папки или файла внутри слоя.                                                      |
| Контракт                  | Публичное API модуля. Снаружи — только через `index.js`.                                                  |
| Bootstrap                 | Файл `src/main.js`. Собирает `logic/` и `ui/`. Вне веток.                                                 |
| Страница                  | Компонент, привязанный к маршруту.                                                                        |
| Блок                      | Переиспользуемый составной компонент.                                                                     |
| Действие                  | Пользовательский сценарий. Имя — глагол.                                                                  |
| Composable                | Функция `use*` с UI-логикой.                                                                              |
| UI-кит                    | Компоненты без бизнес-смысла.                                                                             |
| Логика предметной области | Вычисления, решения, преобразования данных. Не связана с отображением. Живёт только в `logic/`.           |
| UI-логика                 | Реакция на пользователя, состояние отображения, привязка данных к разметке. Живёт в `.vue` и composables. |
|---------------------------|-----------------------------------------------------------------------------------------------------------|
---

## 2. Две ветки

Фронтенд делится на **логику** и **представление**.

- **`logic/`**  — функциональная часть. Не знает о UI.
- **`ui/`**     — визуальная часть.

Зависимость строго в одну сторону: **`ui → logic`**.
Обратная запрещена всегда.

## 4. Слои

### `logic/`
|---------------|---------------------------------------------------------------|
| Папка         | Ответственность                                               |
|---------------|---------------------------------------------------------------|
| `api/`        | Транспорт. Один эндпойнт = одна функция.                      |
| `actions/`    | Один сценарий = одна функция. Оркестрация.                    |
| `store/`      | Состояние и мутации. Без сети. Без логики предметной области. |
| `utils/`      | Чистые функции без состояния и побочных эффектов.             |
| `constants/`  | Справочники, перечисления, лимиты. Не env, не feature flags.  |
|---------------|---------------------------------------------------------------|

### `ui/`
|-----------------|---------------------------------------------|
| Папка           | Ответственность                             |
|-----------------|---------------------------------------------|
| `App.vue`       | Корневой компонент. Только `<router-view>`. |
| `app/`          | Маршруты и guard.                           |
| `pages/`        | Страница = маршрут. Композиция разметки.    |
| `blocks/`       | Переиспользуемые составные блоки.           |
| `composables/`  | UI-логика между страницами.                 |
| `components/`   | UI-кит.                                     |
| `styles/`       | CSS-переменные и глобальные классы.         |
|-----------------|---------------------------------------------|

## 5. `api/` и `actions/` — разные роли

**`api/`** — обёртка одного эндпойнта. Не знает о `store`,
`actions`, `ui`.

**`actions/`** — пользовательский сценарий. Имя — глагол в
терминах пользователя. Может вызвать несколько эндпойнтов,
записать в `store`.

Распределение ответственности:
|-----------------------------------------|-------------|
| Что                                     | Где         |
|-----------------------------------------|-------------|
| URL, заголовки, нормализация транспорта | `api/`      |
| Маппинг ответа в доменную форму         | `api/`      |
| Интерпретация результата                | `actions/`  |
| Запись в store                          | `actions/`  |
|-----------------------------------------|-------------|

Один эндпойнт — в `api/`. Один сценарий — в `actions/`.
Не смешивать.

## 6. Аутентификация
|-------------------------------------------|-----------------------------|
| Что                                       | Где                         |
|-------------------------------------------|-----------------------------|
| Хранение токенов и пользователя           | `logic/store/`              |
| Формирование запросов, подстановка токена | `logic/api/`                |
| Регистрация провайдеров токена            | `logic/actions/`, bootstrap |
| Логин, логаут, refresh                    | `logic/actions/`            |
| Проверка доступа к маршруту               | `ui/app/`                   |
|-------------------------------------------|-----------------------------|

Store не знает о `api/`. `api/` не импортирует store.
Связь — через провайдеры, регистрируемые в `logic/actions/`.

Правила аутентификации:
1. Токен в запрос подставляет `api/`, беря его у провайдера.
2. Провайдер регистрируется в `logic/actions/` при bootstrap.
3. Эндпойнты аутентификации не ретраятся при 401.
4. Повтор запроса после refresh — только один раз.
5. Refresh — single-flight: параллельные 401 делят один refresh-запрос
   (`logic/api/client.js`), иначе ротация токена разлогинивает пользователя.
6. Провал refresh — очистка store без сетевого запроса.
7. Guard восстанавливает сессию до проверки доступа.
8. Logout/unauthorized сбрасывают все доменные store и модульные кэши
   (`resetDomainState`), in-flight загрузки инвалидируются (seq-guard
   в `logic/actions/loading.js`).
9. Неудачное восстановление сессии не оставляет «полу-сессию».
10. Серверные ссылки перед рендером — через `safeUrl` (только `http(s)`).

## 7. Vue SFC и composable

`.vue` содержит разметку, scoped-стили и UI-логику.
Это одна ответственность. Разрывать `.vue` на отдельные файлы
разметки, логики и стилей запрещено.

**Остаётся в компоненте:**
- реактивное состояние для UI;
- обработчики событий;
- валидация формы;
- разметка и scoped-стили.

**Уходит в `logic/`:**
- запросы к API → `api/`;
- сценарии → `actions/`;
- расчёты без UI → `utils/`;
- справочники → `constants/`.

**Уходит в `use*.js` или `composables/`:**
- UI-логика, переиспользуемая в двух и более компонентах;
- UI-логика, не привязанная к разметке;
- UI-логика, которую трудно читать в объёме компонента.

Composable держит UI-состояние, вызывает `actions`, читает store.
Не обращается к API напрямую. Не содержит логики предметной
области. Composable — вынос, а не цель.

---

## 8. UI-кит

Компонент попадает в UI-кит при использовании в **трёх или
более местах**. До этого живёт рядом с местом появления.

UI-кит не знает о бизнесе, store, actions, `logic/`.
Только props, emits, слоты.

---

## 9. Контракты

Папка, которая взаимодействует с другими папками системы, имеет
`index.js` — публичный контракт.

- Снаружи папки — импорт только через её `index.js`.
- Внутри папки — файлы видят друг друга напрямую.
- Изменение внутренностей не ломает внешний код, пока контракт
  сохраняется.

Контракт нужен в: `logic/api/`, `logic/actions/`, `logic/store/`,
`logic/utils/`, `logic/constants/`, `ui/app/`, `ui/composables/`,
`ui/components/`.

Контракт не нужен в `ui/pages/<page>/` — компоненты одной
страницы импортируются по имени файла.

---

## 10. Зависимости

### Между ветками
- `ui → logic` — свободно.
- `logic → ui` — запрещено.

### Внутри `logic/`
Только сверху вниз:
- `actions → api + store + utils + constants`
- `api → utils + constants`
- `store → utils + constants`

Обратные запрещены.

### Внутри `ui/`
Только сверху вниз:
- `app → pages + logic`
- `pages → blocks + composables + components + styles + logic`
- `blocks → components + styles`
- `composables → components + logic`
- `components → styles`

Обратные запрещены.

`app → logic` — только для чтения store и вызова действий,
связанных с доступом.

### Соседи по слою
Модули одного слоя не импортируют друг друга напрямую.

**Исключения:**
- `utils/` — утилиты могут ссылаться друг на друга;
- `constants/` — справочники могут ссылаться друг на друга;
- `components/` — UI-кит внутри может ссылаться на компоненты
  из того же кита;
- `pages/<page>/` — компоненты одной страницы видят друг друга.

`blocks/` не импортирует `logic/`. Данные и вызовы — через props
и emits от страницы. Смысл: блок остаётся переиспользуемым в
любом контексте.

## 11. Поток данных
Компонент → Action → API → Action → Store → Компонент (реактивно)

text

1. Пользователь совершает действие в компоненте.
2. Компонент вызывает действие из `logic/actions/`.
3. Действие вызывает `logic/api/`, получает ответ.
4. Действие обрабатывает результат и пишет в `logic/store/`.
5. Компоненты, читающие нужные ключи store, обновляются
   реактивно.

Ошибки не пишутся в store. Ошибка — значение. Она возвращается
из действия в компонент и обрабатывается локально.

---

## 12. Запреты

1. Сетевые вызовы вне `logic/api/`.
2. Обращение к API из `ui/`.
3. Запись в store вне `logic/actions/`.
4. Логика предметной области в `ui/`.
5. Состояние предметной области вне `logic/store/`.
6. Импорт из `logic/` в `ui/` мимо `index.js`.
7. Импорт из `ui/` в `logic/` любым способом.
8. Импорт слоя выше или соседа по слою (кроме исключений
   раздела 10).
9. Справочники внутри компонентов — только из `logic/constants/`.
10. Общие стили и токены внутри компонентов — только из
    `ui/styles/`.
11. Разрыв `.vue` на отдельные файлы разметки, логики и стилей.
12. Обёртка эндпойнта пишет в store.
13. Действие вызывает сеть напрямую.
14. `blocks/` импортирует `logic/`.
15. `api/` импортирует store.

---

## 13. Размер файла

- Строки — не цель. Сигнал посмотреть внимательнее.
- Файл, который трудно прочитать за один экран, — сигнал.
- Если файл большой — проверить число причин для изменения,
  а не число строк.
- Резать по ответственностям, не по строкам.
- Жёсткий лимит строк запрещён.

---

## 14. Тесты

- Тесты `logic/` живут рядом с кодом.
- Тесты `ui/` живут рядом с компонентом.
- Тесты `logic/` не зависят от Vue, DOM и компонентов.
- Если тест `logic/` требует компонент — тест написан не на
  тот слой.
- Тесты — часть модуля, не отдельный слой.

---

## 15. Порядок работы

- Правила описывают сложившуюся архитектуру, а не план.
- Конкретные домены внутри папок финализируются по факту работы.
- Изменения структуры отражаются в этом документе.
- Правило, которое нельзя проверить грепом или ревью, здесь быть
  не должно.
- Правила короткие. Если правило не влезает на экран — оно
  переписано плохо.
