# Правила работы со временем

## Принципы

1. **Сервер работает только в UTC.** Хранение, сравнения, дедлайны, фоновые задачи — наивный UTC.
   Контейнеры backend и PostgreSQL запущены с `TZ=UTC`; текущий момент — `app.utils.clock.utc_now()`.
2. **Личный пояс — только показ.** У каждого пользователя своё смещение (`timezone_offset`, часы)
   в настройках; при регистрации берётся пояс браузера.
3. **Перевод на границе API.** Клиент (`frontend/src/logic/utils/tz.js`) переводит ответы из UTC
   в пояс пользователя и обратно — значения запросов; периоды (`date_from`/`date_to`) уходят
   на сервер полуоткрытыми UTC-границами местных дат. Остальной клиентский код работает
   в поясе пользователя; «сейчас» — `userNowDate()`.
4. **Сервер сам переводит** только то, что выдаёт готовым текстом или отчётом: время в уведомлениях
   (в поясе получателя) и статистику/детали оплат (в поясе репетитора).
5. **Формат** — ISO 8601. Aware-вход переводится в UTC, а не отбрасывает смещение.
6. **Интервал полуоткрытый** — `[start, end)`.
7. **Максимальная длительность** — 168 часов для уроков и броней.

## Брони

Еженедельные брони задаются в «стенных» часах репетитора (его личный пояс). Свободные окна
строятся по местным датам репетитора и переводятся в UTC (`app/scenarios/student/availability.py`);
окно может проходить через полночь UTC — проверка шага считает от начала непрерывного окна.

## Дедлайны записи/отмены

- `booking_lead_time_hours` — за сколько часов минимум можно записаться. Окно, пересекающее эту
  границу, не выбрасывается: доступна часть с первого начала по шагу от начала окна.
- `cancellation_lead_time_hours` — за сколько часов минимум ученик может отменить урок.
  Свою заявку, ещё не подтверждённую репетитором, ученик может отозвать в любой момент.

## Проекция времени на сетку

Время на графиках проецируется на часовую сетку пропорционально; ячейка — 1 час. На телефоне
сетки расписания и броней показывают 3 дня.
